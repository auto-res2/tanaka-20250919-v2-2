# Experiment Strategy
Experiment 1 – Component Ablation & Contribution Analysis
----------------------------------------------------------------
Goal: Quantify how much each novel sub-module of APEX (Pareto MLP, Temp-scaled Spherical, Elastic-KL, Self-denoising mask) contributes to the four target properties: instruction quality, calibration, knowledge retention, and noise-robustness.

Design
• Model/Data: Llama-2-7B-hf with the full training recipe already described (Alpaca 52 k + noisy ShareGPT; Argilla-DPO preferences). 
• Variants (LoRA r=16, 3 random seeds):
  A0  Full APEX (reference)
  A1  – Pareto MLP → replace by fixed αs=0.33,αp=0.33,αk=0.34
  A2  – Temp-scaled Spherical → ordinary Spherical, freeze τ=1
  A3  – Elastic-KL → single global λ tuned once on dev set
  A4  – Self-denoising mask → conventional entropy re-weighting (no masking)
  A5  – All four removals (degenerates to CALM-style mix)

Metrics (same eval harness): MT-Bench, AlpacaEval, ECE (TruthfulQA-MC), zero-shot MMLU, GSM8K-5-shot, noise stress-test (50 % label flips), GPU hours.

Expected Read-out
• A0 should dominate A1–A5 on every axis within paired t-test α=0.05.
• Largest MT-Bench gap is expected when removing the Pareto MLP (A1), showing adaptive weighting is critical for quality/alignment.
• ECE should worsen most in A2, isolating the temperature-scaled scoring rule’s role.
• Knowledge retention drops sharply in A3, confirming that per-layer KL budgets protect pretrained competence.
• Noise stress-test sensitivity spikes in A4, validating the self-denoising mask.
• A5 should replicate CALM numbers, proving additivity, not mere parameter lucky-shot.
Demonstration: Clear, orthogonal gains from every component certify that the full APEX recipe—not any single trick—achieves the claimed Pareto dominance.

Experiment 2 – β-Sensitivity Curve vs. DPO (Alignment–Calibration Trade-off)
--------------------------------------------------------------------------
Goal: Show that APEX eliminates manual β tuning by staying on or near the Pareto front across the entire alignment/calibration spectrum, whereas DPO moves along a brittle 1-D curve.

Design
• Model: Mistral-7B-Instruct (LoRA r=16).  
• Fixed training setup, but run DPO for β∈{0.01,0.1,0.3,1,3,10}.  Run APEX once (no hyper-parameter search).
• For every checkpoint, measure: (1) MT-Bench, (2) ECE, (3) MMLU delta, (4) Toxicity-avoidance win-rate.
• Plot four heat-maps: metric value vs. β; overlay horizontal APEX line.

Expected Read-out
• DPO exhibits strong metric trade-offs: high β → good alignment but disastrous ECE/knowledge; low β → opposite.  Sweet-spot narrow.
• APEX single point lies inside the upper-right quadrant for all four plots—matching or exceeding DPO’s per-metric optimum simultaneously.
Demonstration: The adaptive Pareto MLP makes APEX “set-and-forget”, automatically landing on a near-optimal alignment/calibration compromise that DPO can reach only by exhaustive β sweeps.

Experiment 3 – Plug-and-Play Scalability & Generalisation
---------------------------------------------------------
Goal: Validate that APEX really is a drop-in loss usable across model sizes, domains, and hardware budgets with negligible overhead.

Design
• Models:  
  – Phi-2-2.7B (single A100-80 GB)  
  – Llama-2-13B (2×A100-80 GB)  
  – Llama-2-70B (8×A100-80 GB, ZeRO-3)
• Domains / data:  
  – General instruction (Alpaca+ShareGPT, 20 % noise)  
  – Code synthesis (Code-Alpaca 20 k + 2 k preference pairs)  
  – Medical QA (MedAlpaca 8 k + 1 k physician preference pairs)
• For each (model, domain) pair run CE baseline and APEX with identical LoRA configs; log:   
  – Main domain metric (e.g. HumanEval pass@1, MedQA-USMLE accuracy)  
  – ECE on in-domain multiple-choice val set  
  – Zero-shot MMLU (knowledge bleed)  
  – Wall-clock hours and peak GPU memory
• Record lines of code changed: diff of training script (should be <100).

Expected Read-out
• APEX yields consistent +2‒6 % absolute gains on domain metrics across all three model sizes while cutting ECE by ≥30 % and keeping MMLU drop <1 %.
• Compute overhead ≤8 % in GPU hours; memory overhead negligible (<0.3 GB from MLP & buffers).
• Code diff ≤70 lines for all experiments, visually proving simplicity.
Demonstration: Confirms APEX scales from 2.7 B to 70 B parameters, handles specialised domains, and really is a low-friction, resource-friendly plug-in—addressing practical adoption concerns.

Collective Outcome
These three orthogonal experiments (granular ablation, hyper-parameter-free robustness, and cross-domain scalability) will jointly demonstrate that APEX-Loss is (1) internally well-engineered, (2) externally robust without tuning, and (3) practically deployable, thereby validating the core research claims.
